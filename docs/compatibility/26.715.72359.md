# Codex Desktop 26.715.72359 compatibility

Status: **candidate profile enabled; Browser bridge live-validated**

Inspected on 2026-07-23 from the installed `/Applications/ChatGPT.app`:

- Codex Desktop: `26.715.72359` (bundle build `5718`)
- Bundled CLI: `codex-cli 0.145.0-alpha.30`
- App ASAR SHA-256: `6c6528eb1e8450cdc506a59586f8caffe87576e200977e2a11bdea0cecf1c718`
- The packaged ASAR still contains `composer-surface-chrome`,
  `data-codex-composer`, `quick-chat-prewarm`,
  `selectedTextOverlay.quickChatPrompt`, and `avatar-overlay` markers.
- The bundled CLI protocol version is unchanged from the fully live-validated
  `26.715.72028` profile.

The profile reuses `desktop-v1`. Runtime checks still require a matching main
`app://` target, a visible Files row, and a dedicated ChatGPT Quick Chat composer
before any text is inserted. A mismatch fails closed
and falls back to clipboard handoff.

The `v0.4.0-preview` Browser bridge was live-validated against this build:

- The Companion served the real IDE on a random `127.0.0.1` port.
- Codex built-in Browser loaded the authenticated page and the URL fragment was
  removed after the token entered `sessionStorage`.
- The page restored the real Workspace and reported the machine's real Java
  `JDK required` state with Setup and Recheck controls.
- Browser mode omitted Pin, while the native window retained it.
- With Codex running without the required CDP launch argument, opening the
  Companion IDE failed closed to the native window.

An end-to-end click on the injected Sidepanel `IDE` row still requires relaunching
the currently active Codex process with a random loopback-only CDP port. That
disruptive relaunch was intentionally not performed while this task was active.
The Browser-first target and handshake path remain preview compatibility behavior;
failure or an unknown Codex version falls back to the native IDE.

The controller does not modify the Codex app, ASAR, signature, or private IPC.
